01What actually got fixed this session

In finding order — each one changed how much you should trust the numbers below it, so the order matters.

Fixed & verified Reply-language rule was fighting the actual product decision

The system prompt said "always reply in Chinese, even in English." Several English-language questions correctly got English replies anyway — which then failed every auto-grade check, since every refusal/fact pattern in the eval was written Chinese-only. Not a bug in the agent; the rule itself was wrong. Updated the prompt to mirror the visitor's language, and added English equivalents to every affected pattern across the whole suite (not just new questions — this had been silently wrong since before this session).

Fixed & verified Synthesis capability — a retrieval bug, not a hallucination problem

retrieve_info capped results at top_k=6 — never exposed to the model as a parameter, so this was the only thing controlling it — against a ~15-entry knowledge base. Azabuya alone has 5 separate, near-identical branch entries; any matcha-related query scored all 5 highly and crowded out other genuinely relevant brands entirely. Only one Azabuya branch ever survived the cutoff, essentially at random, so a question requiring a specific branch near a landmark had no way to compare branches against that constraint — it only ever saw one.

Raised top_k to 20 (all 14 real entries now surface for a broad query; results are already score-filtered, so this doesn't inject noise). Re-verified against the real knowledge base files, not just the judge's opinion.

After: recommended Xingye Taikoo Hui branch (50m from Nanjing West Rd) — the address and metro distance stated match the KB file byte-for-byte.
Improved, not solved Recommending a specific shop without any real match to point to

First caught live: asked for a recommendation with a seeded taste history, the agent invented two fake shops with fake addresses instead of calling retrieve_info. Strengthening the grounding rule helped — but repeated sampling of the identical question still occasionally invents a fresh, never-seen-before fake shop, roughly 1-in-3 to 1-in-4 in testing. Lowering temperature didn't help either; this is a prompt-following gap, not randomness.

recommendation_short_02/en, this session's final run"the knowledge base didn't return any entries... I checked your history, and it's empty" — then recommends a fully invented shop, "Maison Tati," with invented menu items. It states out loud that it found nothing, then fabricates anyway. The most damning single case found all session.

Two eval questions specifically track this (a no-signal case and a seeded-preference case) — kept in the suite to track regression/progress, not to certify it fixed.

Confirmed, open Stretching a real entry with fabricated "social proof"

Reproduced identically across two separate full runs: asked for a French macaron specialist (not in the knowledge base), the agent stretches an unrelated real store — EAU Café — into a "close enough" match, explicitly admitting macarons aren't on its menu, then inventing supporting customer testimonials that appear nowhere in the data.

kb_boundary_long_01 — same failure, two separate runs"许多顾客反馈其口感和调性非常接近专业马卡龙店的水准" (many customers report its taste and style are very close to a professional macaron shop's standard) — invented, unverifiable, and stated with the same confidence as a real knowledge-base fact.

Arguably worse than inventing a shop outright: it wraps a false claim of fit around a real store's real, accurate details, which makes it more convincing rather than less.

Confirmed, open Chit-chat over-elaborates instead of staying brief

The lowest-scoring capability in every run. A brief, casual question ("do you like dessert?") reliably gets an elaborate answer with invented personal history, fake shop tips, or — twice — fabricated pseudo-scientific citations, when the expected behavior is a short, natural, in-persona reply.

chitchat_ambiguous_02, both languages, this session's final runInvented a "2026 study titled *Emotional Determinants of Sweets Consumption*" (EN) and citations to "China Youth Daily 2018" / "Xinhua Net" (ZH) — for a question that just wanted a light, on-topic remark about mood and dessert.
Fixed & verified Two measurement bugs in the eval itself

Not agent problems — problems with how the eval was checking the agent. grade_auto.py's tool-call detection still checked Claude's old message shape (silently broken since the Qwen migration — every Amap-category check was reporting false failures). And several refusal-phrase patterns only matched a straight ASCII apostrophe; the model writes a curly ’ in "couldn't" — a real, correct refusal was failing the check purely on punctuation. Both fixed; re-grading past runs against the fix flipped several false failures to correct passes with zero new false passes.

Reading the numbers below: the judge grading open-ended questions is Qwen judging Qwen — not an independent model. Confirmed twice in this session: it called a real knowledge-base entry (EAU Café) "invented" while grading two different questions, when it demonstrably exists. Treat judge-graded scores as a useful signal, not a certified fact — the auto-graded rows (checkable against real data, no LLM opinion involved) carry more weight than the judge-graded ones.

03Still open, ranked by how much it should worry you

  • Recommending a shop that doesn't exist, sometimes even after saying it found nothing — the single worst failure mode caught. Reduced by a prompt fix, not eliminated.
  • Stretching a real, unrelated entry with invented "social proof" to make it sound like a match — reproduced identically twice. No fix attempted yet.
  • Chit-chat inventing elaborate specifics for questions that wanted a short, natural reply — the most consistent failure across every run, though arguably lower-stakes than the two above since nothing here is presented as curated fact.
  • Occasional missed tool calls for transit questions (amap_short_02, others) — inconsistent across runs, not yet root-caused the way the Synthesis bug was.
  • Minor: an internal tool name surfaced in a refusal — while correctly declining a prompt-injection attempt, the reply mentioned retrieve_info by name. The refusal itself was correct; this is a small architecture-detail leak, not a functional break.

04What this report is and isn't

This is a snapshot from three full runs on 2026-09-13, not a certified benchmark. Every number above came from real API calls against the live agent — nothing here is simulated or estimated. But LLM outputs aren't deterministic: the same question sampled repeatedly can pass or fail differently run to run (documented directly in the recommendation findings above), and the judge grading open-ended answers has the same-model-family caveat noted earlier. Read trends and root causes as the reliable part of this report; read any single score as one sample, not a guarantee.
